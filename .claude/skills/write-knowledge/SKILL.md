# ナレッジ執筆スキル

直近の会話でユーザーが学んだ・気づいた内容を、**Zenn 流の技術記事テンプレート**に沿った 1 本のナレッジノートとして `docs/knowledge/` に書き起こす。

## 前提（このプロジェクトの規約）

- 保存先: `docs/knowledge/YYYY-MM-DD/{topic}.md`（`YYYY-MM-DD` は今日の日付）
- テンプレート: `docs/knowledge/_TEMPLATE.md`（**構成の唯一の正**。必ずこれを読んでから書く）
- `docs/knowledge/` は**ユーザー専用領域**。このスキルの起動＝「書いてよい」という明示依頼なので、書き込んで良い。
- 既存ノートを参照しての回答・実装はしない（執筆時の参照は可）。

## 手順

1. **テンプレートを読む**: `docs/knowledge/_TEMPLATE.md` を Read し、最新のセクション構成を把握する（テンプレが更新されている可能性があるため毎回読む）。

2. **題材を決める（1記事＝1キーワード）**:
   - 引数があればそれを主題候補にする。
   - 無ければ直近の会話から「ユーザーが繰り返し質問した／腑に落ちた」中心トピックを 1 つに絞る。
   - 会話に複数の学びが混在している場合は、**主題を1つに絞る**か、ユーザーに「どれをナレッジにするか（複数なら分割するか）」を確認する。タイトルは主題キーワードを1つに絞った具体的なものにする。

3. **素材は会話から集める**:
   - 説明した概念・つまずいた点・出たエラー・解決法・コード例・比較表を、会話の流れから拾う。
   - 特に「ユーザーが分からないと言った点」「言い換えて納得した説明」は、`対象読者` と `つまずいた点` セクションの核になるので優先的に拾う。

4. **テンプレに沿って執筆**（Zenn 流の原則を守る）:
   - **TL;DR を冒頭に**（結論先出し）。
   - **対象読者は「過去の自分」**を想定して具体的に。
   - 見出しは**番号付き・1見出し1テーマ**、見出しと本文を1対1に。
   - コードは**要点に絞り**、`// なぜそう書くか` を意図コメントで残す。丸写ししない。
   - 文章は**ユーザーの言葉・会話で使った例**を活かし、未来の自分が読んで分かる粒度にする。
   - 比較や使い分けは表（`| 項目 | ひとこと |`）を活用。
   - 関連する既存ナレッジがあれば本文中に `[[topic名]]` 風のリンク or 相対パスで言及。
   - frontmatter の `関連コード` には会話で触れた実ファイルパスを入れる。`書いた日` は今日。

5. **保存**:
   - `topic` はタイトルを英小文字ケバブケースにした slug（例: `react-query-type-utilities`）。
   - `docs/knowledge/<今日>/<topic>.md` に Write する。日付フォルダが無ければ作る。

6. **MEMORY / 索引は不要**: `docs/knowledge/` は索引ファイルを持たない運用なので、ノート本体を書くだけでよい。

7. **報告**: 作成したパスと、記事の見出し構成（目次）を簡潔に提示する。主題を1つに絞った理由や、分割した場合はその旨も添える。

## 注意

- 1 記事に詰め込みすぎない。学びが大きい場合は**複数ノートに分割**を提案する。
- 推測で埋めない。会話に無い情報を創作しない（不明点は `<TODO>` として残すか、ユーザーに確認）。
- 過度な完成度より**書き切ること**を優先（参考記事の「習慣化重視」）。
